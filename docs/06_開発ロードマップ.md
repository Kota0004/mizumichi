## 優先順位の考え方

**「データの質」＞「機能の数」。**
危険箇所95箇所が正確に登録され、雨量が正しく取れていれば、UIが素朴でも役に立つ。
逆に、綺麗なUIでも地点データが不正確なら害になる。**1-A（データ基盤）に最も時間を割く。**

## 最初の一歩（今週やること）

ツールは揃っているので、残りは**外部データを取りに行くだけ**。

```bash
pip install -r tools/requirements.txt
./tools/run_tests.sh          # まず全部通ることを確認
```

1. **PDFを入手する** — 国交省 千葉国道事務所 <https://www.ktr.mlit.go.jp/chiba/chiba_index030.html>
   ```bash
   python3 tools/build_spots.py --pdf 一覧表.pdf --dump-text | head -50   # 何が読めるか確認
   python3 tools/build_spots.py --pdf 一覧表.pdf --area chiba --out data/spots_chiba.json
   python3 tools/enrich_dem.py --in data/spots_chiba.json --out data/spots_chiba.json
   ```
   → `data/spots_chiba.review.csv` を開いて **needs_review=YES の座標を地図で確認**する。ここが山場。
2. **気象庁アメダスに疎通する**
   ```bash
   python3 tools/fetch_amedas.py --spots data/spots_chiba.json --out data/risk_latest.json
   ```
   スキーマが想定と違えばここで落ちる。落ちたら `ELEMS` / `station_points()` を実レスポンスに合わせる。
3. **千葉市システムを調べる**
   ```bash
   python3 tools/probe_endpoints.py --url https://pub.os-alert.info/chiba/devmap --browser
   ```
4. **打診を出す** — [08_自治体連携_打診文案.md](08_自治体連携_打診文案.md)（優先順: 千葉国道事務所 → 千葉市 → 気象庁 → 千葉県）
