# 03. 要件定義

作成日: 2026-08-19 / プロダクト仮称: **みずみち（MizuMichi）**

---

## 1. プロダクトの定義

> **冠水しやすい道を、雨量に応じて事前に知らせ、走行中は手前で止めるアプリ。**

守るべき原則（設計判断に迷ったらここに戻る）:

1. **安全側に倒す** — 迷ったら「危険」と言う。ただし出しすぎると無視されるので、レベルを分ける。
2. **運転を邪魔しない** — 走行中の操作を要求しない。音声と最小限の表示のみ。
3. **断定しない** — 「通行止め」と断定できるのは公的情報のみ。それ以外は「可能性」として表現する。
4. **オフラインでも死なない** — 豪雨・停電時に通信が細る前提。危険箇所データは端末にキャッシュする。

## 2. スコープ

### 対象
- 自動車ドライバー（自家用・配送）を第一ターゲット。
- 対象エリア: **MVPは千葉県**（背景の事象、95箇所の公的データ、千葉市のセンサー実例が揃っている）。→ 首都圏 → 全国。

### 非対象（少なくとも初期は扱わない）
- 河川の外水氾濫からの広域避難誘導（キキクル・自治体の避難情報に委ねる）
- 徒歩・自転車の詳細な安全誘導（表示はするが最適化しない）
- 冠水後の被害査定・保険・車両撤去の手配

## 3. 機能要件

優先度: **[MVP]** 必須 / **[P2]** フェーズ2 / **[P3]** 将来

### 3-1. 地図・危険箇所の閲覧

| ID | 機能 | 優先 | 内容 |
|----|------|------|------|
| F-01 | 危険箇所マップ | MVP | 地理院タイル上に冠水危険箇所（点／区間）を表示。色＝現在の危険度。 |
| F-02 | 箇所の詳細 | MVP | 名称・種別（アンダーパス／低地／橋詰め）・想定水深・過去の冠水履歴・出典。 |
| F-03 | 雨量レイヤ重ね合わせ | MVP | 降水ナウキャスト（実況・30分先）と浸水キキクルをオーバーレイ、透明度調整。 |
| F-04 | ハザードマップ重ね合わせ | P2 | 浸水想定区域・内水浸水想定区域。 |
| F-05 | 過去事例の表示 | P2 | 「2026-08-13の豪雨でここは水没した」を写真つきで表示。**説得力が最も高い情報**。 |

### 3-2. 降水量フィルタ（ユーザー要望の中核）

| ID | 機能 | 優先 | 内容 |
|----|------|------|------|
| F-10 | **雨量シミュレーションスライダー** | MVP | 「時間雨量 30 / 50 / 80 / 100 mm」を選ぶと、**その雨が降ったときに危険になる箇所だけ**が地図に残る。「もし〜なら」を体験させる機能。 |
| F-11 | 現在雨量モード | MVP | 実際のリアルタイム雨量（アメダス＋ナウキャスト）を適用して現在の危険度を表示。 |
| F-12 | 予測モード | P2 | 30分先／1時間先の予測雨量で危険度を表示。「今から出ると帰りが危ない」を伝える。 |
| F-13 | 危険度しきい値フィルタ | MVP | 「レベル3以上だけ表示」など、表示する危険度の下限を選べる。 |
| F-14 | 種別フィルタ | P2 | アンダーパスのみ／通学路のみ／自分の通勤ルート上のみ。 |

### 3-3. 現在地アラート（ユーザー要望の中核）

| ID | 機能 | 優先 | 内容 |
|----|------|------|------|
| F-20 | **接近アラート** | MVP | 危険度が閾値以上の箇所に**半径300〜500m**まで近づいたら通知。走行中は**音声読み上げ**（「500m先、アンダーパス。冠水の可能性があります」）。 |
| F-21 | 進行方向判定 | P2 | 単に近いだけでなく、**そこへ向かっているか**を進行方位から判定し、誤報を減らす。 |
| F-22 | エリア警戒アラート | MVP | 現在地の1kmメッシュのキキクルが「警戒」以上になったら通知。 |
| F-23 | 出発前チェック | P2 | 登録ルート（自宅↔職場など）上の危険箇所を、指定時刻に事前通知。 |
| F-24 | 静音・運転モード | MVP | 通知の頻度上限、深夜の抑制、運転中は音声のみ。 |
| F-25 | 同乗者向け画面 | P3 | 大きなボタンで「今すぐ引き返す／迂回」を選べる簡易UI。 |

### 3-4. ユーザー投稿（速報性の担保）

| ID | 機能 | 優先 | 内容 |
|----|------|------|------|
| F-30 | 冠水報告 | MVP | 現在地＋水深の目安（くるぶし／膝／それ以上）を**3タップで**投稿。写真は任意。 |
| F-31 | 投稿の地図反映 | MVP | 一定の信頼度を満たした投稿を「未確認情報」として地図に別スタイルで表示。 |
| F-32 | 時間減衰 | MVP | 投稿は時間で信頼度が減衰し、一定時間で自動的に消える（デフォルト3時間）。 |
| F-33 | 相互検証 | P2 | 「まだ冠水している／もう引いた」の追認ボタン。複数一致で信頼度上昇。 |
| F-34 | 通報の悪用対策 | MVP | レート制限、位置の妥当性検証（投稿位置と実測GPSの乖離）、通報機能。 |

### 3-5. 迂回・ルート

| ID | 機能 | 優先 | 内容 |
|----|------|------|------|
| F-40 | 危険箇所を避けるルート提示 | P2 | 危険度が閾値以上の箇所を avoid polygon としてルーティングエンジンに渡す。 |
| F-41 | 既存ナビへの受け渡し | MVP | 迂回先の目的地を Google マップ等に URL スキームで引き渡す（自前ナビは作らない）。 |
| F-42 | ルート上の危険箇所一覧 | P2 | 出発前に「このルートには危険箇所が2つあります」と提示。 |

### 3-6. 自治体・管理者向け（収益・持続性）

| ID | 機能 | 優先 | 内容 |
|----|------|------|------|
| F-50 | 管理ダッシュボード | P3 | 投稿の集計、優先確認箇所のランキング、危険箇所マスタの編集。 |
| F-51 | 公式情報の投入 | P3 | 自治体が「通行止め」を確定情報として入力し、アプリに即時反映。 |

## 4. 非機能要件

| 区分 | 要件 |
|------|------|
| 可用性 | **豪雨時にこそ落ちない**。ピークは平常時の数十倍。危険箇所データはCDN配信の静的ファイルにし、DBに依存させない。 |
| 遅延 | 雨量データ取り込みから危険度反映まで **3分以内**（ナウキャスト5分更新に対し遅延を最小化）。 |
| オフライン | 危険箇所マスタと直近の危険度を端末にキャッシュし、**圏外でも地図と接近アラートが動く**。 |
| 電池 | バックグラウンド測位は**ジオフェンス／significant-change**を基本とし、常時高精度測位はナビ利用中のみ。 |
| プライバシー | 位置情報は原則**端末内で処理**。サーバへ送るのは投稿時のみ。個人特定情報を持たない。 |
| アクセシビリティ | 色覚多様性に配慮（色＋形＋文言）。音声読み上げ対応。 |
| 表現 | 断定を避け、必ず「最終判断は現地の状況で」の注意書きを添える。 |
| 対応環境 | iOS 16+ / Android 10+ / モダンブラウザ（PWA版）。 |

## 5. 受け入れ基準（MVPの完成条件）

- [ ] 千葉県内の公的な冠水注意箇所（95箇所）が座標付きで地図に表示される。
- [ ] 雨量スライダーを50mm/hにすると、閾値50mm/h以下の箇所だけが危険色になる。
- [ ] 実際のアメダス／ナウキャストの値が取り込まれ、10分以内の鮮度で危険度が更新される。
- [ ] 危険度3以上の箇所の500m以内に入ると、アプリを閉じていても通知が届く。
- [ ] 3タップで冠水報告ができ、他の端末の地図に3分以内で反映される。
- [ ] 機内モードにしても、地図と危険箇所と接近アラートが動く。
- [ ] 通知の文言に断定表現がなく、免責が併記されている。

## 6. 意図的に「やらないこと」

| やらないこと | 理由 |
|------------|------|
| 自前のターンバイターンナビ | 開発コストが本質でない。既存ナビへ引き渡す。 |
| 水深のcm単位での断定 | 推定精度が出ない。誤った安心を与える方が危険。段階表示に留める。 |
| 全国一律の雨量閾値 | 役に立たない（→01の第4節）。地点別閾値で持つ。 |
| SNSクロールによる自動判定（初期） | 誤情報の混入リスクが高く、検証コストが見合わない。P3で再検討。 |
